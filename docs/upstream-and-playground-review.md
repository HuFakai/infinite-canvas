# 上游与生图参考项目功能审查

本文档用于回答两个问题：

1. 上游在上次合并后又新增了什么，哪些能力适合当前纯生图主线。
2. `CookSleep/gpt_image_playground` 中哪些实现值得借鉴，哪些不能直接照搬。

本文先记录审查结论和后续路线；“实施记录”及表格中的“已实现，待测试”表示能力已完成本地适配，但在用户验收前不会写入正式功能说明。

## 审查基线

| 对象 | 快照 | 说明 |
| --- | --- | --- |
| 当前项目 | `main@61fcd7c` / `v0.3.5` | Next.js + Go 后端，保留账号、算力点、渠道代理、会员支付、同步和对象存储 |
| 上次上游基线 | [`basketikun/infinite-canvas@8cbe00e`](https://github.com/basketikun/infinite-canvas/commit/8cbe00e3486eec00bcaf21a7c5e55fefddf28500) | 已审查并合入 Gemini、生成停止和 Canvas Agent 纯生图子集 |
| 上游最新快照 | [`basketikun/infinite-canvas@f76f81c`](https://github.com/basketikun/infinite-canvas/commit/f76f81c4c75c5900a2141b6c08011bed4d3e8a22) | 包含 `v0.5.0` 至 `v0.10.0` 以及 `v0.10.0` 后的未发布提交 |
| 生图参考项目 | [`CookSleep/gpt_image_playground@85af989`](https://github.com/CookSleep/gpt_image_playground/commit/85af98984d866c574f7007245b3acded250efa6b) / `v0.7.1` | Vite 纯前端生图工作台，重点审查协议兼容、图片处理、缓存和测试实现 |

上游在该区间已经从 Next.js 迁移到 Vite，并移除了原 Go 后端。当前项目则继续使用 Next.js App Router、Go/Gin、GORM 和服务端渠道代理，因此大部分功能只能按行为重新适配，不能直接整体 cherry-pick。

## 结论摘要

- 最优先的上游适配项是高分辨率图片编辑稳定性、可拖拽切图线、多文件上传和安全的配置导入导出。
- 最值得从 `gpt_image_playground` 借鉴的是遮罩预处理、响应解析测试夹具、实际参数追踪和自定义响应映射思路。
- 当前已有的 Gemini、生成停止、Agent 附件/停止/客户端隔离、URL/Base64/SSE 图片识别不应重复实现，只补充缺失场景和测试。
- 上游的纯前端化、WebDAV、视频/音频、任意 JavaScript 渠道脚本和无隔离远程插件不进入当前主线。
- 视频/音频更新已经审查，但当前 `main` 保持纯生图定位；本轮也不更新 `codex/video-audio-upstream-v0.3.3`。

| 功能 | 建议 | 原因 |

| 多收藏夹、拖拽排序、收藏夹 ZIP | 作为素材分类增强候选 | 当前已有分类和“我的素材”，需先统一两套分类概念 |
| 多份备份合并导入 | 等账号同步冲突规则明确后再做 | 当前同时存在本地数据、账号快照和对象存储，不能只按 ID 覆盖 |
| 本地绿幕/洋红幕透明背景后处理 | 作为实验功能，不替代正式抠图 | 对发丝、半透明和相近颜色容易产生错误边缘 |
| fal.ai 队列 | 暂不单独接入 | 应先完成通用声明式异步渠道映射，避免每个供应商增加一套代码 |
| PWA、浏览器通知 | 低优先级 | 不解决当前主要的生成稳定性和渠道兼容问题 |
| Agent 多轮分支 | 仅借鉴状态模型 | 当前 Canvas Agent 面向画布操作，不能直接替换成独立生图对话产品 |

### 已有能力只补测试

- 大图下载已经改为读取原始 Blob，不再通过字符串转换；借鉴下载项目时只补文件完整性测试。
- 图片 URL、Base64、Responses 流式图片和破损 JSON 已有容错逻辑；借鉴参考项目时只补规范化测试和明确错误。
- 当前已经使用 IndexedDB/localforage、账号快照和可选 S3/R2；不能替换成参考项目的纯 IndexedDB 数据库。
- 当前渠道密钥可以由服务端管理；不能采用参考项目将全部 API Key 保存在浏览器的默认架构。

## 实施记录

### P0：稳定性基础

1. 统一裁剪、遮罩和切图的高分辨率编辑视口。
2. 增加遮罩工作图预处理，确保原图和 mask 同尺寸、同格式。
3. 建立图片接口故障模拟器和响应解析测试夹具。

### P1：直接提升创作效率（已适配，待测试）

1. 切图支持拖拽分割线和非等分切片。
2. 上传和拖拽支持多文件，并接入现有存储生命周期。
3. 记录并展示上游真实参数和改写后提示词。
4. 提供默认不含密钥、可预览的配置导入导出。
5. 增加火山方舟/Seedream 生图协议适配，不引入视频字段。

### P2：大型交互与扩展能力（已适配，待测试）

1. 左侧资产/提示词面板和通用组节点。
2. 统一提示词标准 JSON 来源与缓存，不运行来源脚本。
3. 增加后台渠道的声明式请求/结果映射。
4. 优化历史缩略图缓存和 Agent 全站任务状态。

## 合并原则

- 纯生图优先：不因为上游存在对应提交而恢复视频或音频能力。
- 后端能力优先：会员、支付、账号、渠道、算力点和 AI 日志必须继续经过 Go 服务。
- 声明式配置优先：协议差异使用受约束字段映射，不执行任意远程脚本。
- 数据生命周期优先：新功能必须兼容本地 Blob、账号快照和 S3/R2 对象存储。
- 小批次适配优先：按功能行为移植并逐项测试，不整体合并上游 Vite 架构。
